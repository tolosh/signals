# ADR 0003: Living-expense methods

Status: X-1 to X-4 proposed for review on SIG-47

Product Specification §6.3 (AF-E1 to AF-E5) and §6.6 make the expense method workspace
configuration, and Decision Record D26 (7 November 2026) rules that every method is built now.
The specification is the source of truth; this records where the engine had to interpret it. The
code cites these as X-1 to X-4 in `src/engines/affordability/expenses.ts`.

| ID  | Question                                    | The engine does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| X-1 | Which methods exist                         | §6.3 names one method, the AF-E3 default (higher of confirmed, benchmark, and observed committed plus basic), and the three inputs it uses. The engine offers that default, each input on its own (`confirmed`, `benchmark`, `observed`), and `higher_of_confirmed_benchmark`, which SIG-47 lists. SIG-47 calls that last one "the current default", but AF-E3 and AF-T1 make the three-way method the default ($3,367, not $3,000), so the default stays AF-E3. §6 defines no "committed plus discretionary" or benefit-adjustment variant, so none is built. |
| X-2 | A "higher of" method with one input missing | It is unverified with `resolve_with`, rather than taking the higher of the inputs present, because SIG-47 forbids quietly substituting. In live use the default method is therefore unverified until observed expenses exist (SIG-17, SIG-43).                                                                                                                                                                                                                                                                                                                 |
| X-3 | AF-E5 rent ending at settlement             | It is removed from observed committed expenses, and the trace shows `rent_removed_monthly`. Confirmed and benchmark figures are left as given.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| X-4 | AF-E2 one-off exclusion                     | It belongs to deriving the observed averages (SIG-17), not to choosing a method, so the engine takes observed figures after that exclusion.                                                                                                                                                                                                                                                                                                                                                                                                                    |

When expenses are unverified, ARA, DSR, NDI and Benchmark/GLE are `unverified` and the affordability
status is `unverified` with `resolve_with`. LVR, LTI and DTI do not use expenses and are still computed.
